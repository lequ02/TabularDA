load_data <- function(csv_path) {
df = read.csv(csv_path)
df$has_y = as.factor(df$has_y)
df$tvae = as.factor(df$tvae)
df$method = as.factor(df$method)
df$approach = as.factor(df$approach)
df$dataset = as.factor(df$dataset)
df$y_synth = as.factor(df$y_synth)
return (df)
}
summary_table <- function(df, exclude_list_for = c("method", "macro_max")) {
# Check if the input is a dataframe
if (!is.data.frame(df)) {
stop("Input must be a data frame.")
}
# Get column names
col_names <- names(df)
# Apply the 'unique' function to each column and get the list of unique values
unique_values_list <- lapply(df, unique)
# Calculate the count of unique values for each column
unique_counts <- sapply(unique_values_list, length)
# Convert the list of unique values to a character string representation

# Conditionally exclude the list for specified columns
unique_values_strings <- sapply(col_names, function(col_name) {
# Check if the current column name is in the exclusion list
if (col_name %in% exclude_list_for) {
# Return an empty string or a placeholder if the list should be excluded
return("[List Excluded]") # Or use "" or NA_character_ if preferred
} else {
# Otherwise, get the unique values for this column
vals <- unique_values_list[[col_name]]
# Sort values for consistency. This might error if types can 't be compared.
vals_sorted <- sort(vals)
# Paste the sorted values into a single string
paste(as.character(vals_sorted), collapse = ", ")
}
})

summary_df <- data.frame(
ColumnName = col_names,
UniqueCount = unique_counts,
UniqueValues = unique_values_strings,
row.names = NULL # Optional: removes row names
)
# Return the resulting table
return(summary_df)
}
1. Introduction
Generating high-fidelity synthetic tabular data is challenging due to complex data distributions (multimodal,
imbalanced) and mixed data types (discrete/continuous). While generative models like CTGAN & TVAE
have advanced the field, a gap remains between synthetic and real data quality. We propose a decoupled
method, improving synthetic data realism by 11% compared to SOTA models.

The table shows the linear dependencies (aliasing) among the coefficients. Specifically:
has_y1:y_synthctgan, has_y1:y_synthtvae, tvae1:y_synthctgan, tvae1:y_synthtvae: These two-way inter-
action terms involving the ctgan and tvae levels of y_synth are aliased. They are linearly dependent on their
corresponding main effects (y_synthctgan, y_synthtvae, tvae1). For example, when it is y_synthctgan, we
automatically know it is also has_y1 because has_y0 does not exist for y_synthctgan.

6. Mixed-Effects Modeling (LMER)
Justification for Using LMER
While the previous linear models (LM) helped explore interactions and main effects, they treat all factors as
fixed. However, our data has a structure where observations might not be fully independent. Specifically, F1
scores are likely correlated within the same dataset because different methods are applied to it. Furthermore,
we might consider y_synth (the synthesizer for the target variable) and tvae (whether TVAE was used for
feature synthesis) as sources of random variation, representing a sample from a larger population of possible
datasets or synthesis configurations.
A Linear Mixed-Effects Regression (LMER) model is well-suited for this situation. LMER allows us to:
1. Model Non-Independence: Explicitly account for the correlation of scores within the same dataset (or
other grouping factors) by treating dataset as a random effect. This leads to more accurate standard
errors and p-values for our fixed effects.
2. Estimate Variance Components: Quantify how much of the total variation in F1-macro scores is
attributable to differences between datasets, between y_synth methods (if treated as random), or
between tvae usage, versus the residual (unexplained) variation.
3. Generalize Findings: By treating factors like dataset or y_synth as random effects, we aim to make
inferences about the broader population from which these levels were sampled (e.g., performance across
20

PAGE 21
various potential datasets or synthesis methods), rather than just the specific ones included in this
study.
Therefore, we transition to LMER to appropriately model the data structure and draw more robust conclu-
sions about the fixed effects of interest while accounting for random variability.
Goals:
1. We want to see if the new > old (for approach), with dataset, tvae, & y_synth as a random ef-
fect. Meaning, the new approach is better for potentially any dataset, any X_synthesizer, and any
y_synthesizer.
2. We want to see if including y when training the X_synthesizer is better than not including y. I.e,
has_y = 1 > has_y=0

Even though we expect nonEst for the contrast of has_y=0 because the data isn’t available (also because
it is not a valid configuration: approach_old must be has_y=1), we still have a contrast estimate. This
is because: In the model (model_one_inter = lm(formula = macro_max ~ y_synth * dataset + has_y +
tvae, data = df_nog)), “has_y” is included as a main effect. It is not interacted with “y_synth”.
Because has_y is only a main effect, the model assumes that the effect of changing has_y from ‘1’ to ‘0’ is
additive and constant across all levels of y_synth.
The model estimates the main effect of y_synth = ‘ctgan’ primarily from the data where has_y = 1 (since
that’s where ctgan exists). It then estimates the main effect of has_y (the difference between has_y=0 and
has_y=1).
To get the EMM for (y_synth = ‘ctgan’, has_y = 0), it effectively takes the estimated performance of ctgan
(learned from has_y = 1 data) and adjusts it by the main effect of has_y to predict what it would have
been if has_y were 0.
This is a form of model-based extrapolation. The EMM is mathematically calculable from the model’s
coefficients.
Because the estimation for has_y=0 is an extrapolation from has_y=1, it explains why the 2 values are
exactly the same.
However, only the estimation for has_y=1 is valid (because the other configuration is not viable)
