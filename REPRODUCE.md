# Reproducing the results

This guide is for readers working from a clone of this repository, without access
to the authors' workstation or research server. It covers the real-data matrix,
the validation-best checkpoint selection, the statistical analysis, the simulated
benchmark, and the manuscript exhibits.

## What the repository contains

- Code: `src/` (preparation, generators, labelers, downstream models), `scripts/`
  (experiment runners, validation-best replay, report builders) and
  `simulated_eval/` (known-distribution benchmark).
- Reported scores: `comparisons/` holds the comparison tables and figures.
  `comparisons/scores.csv` lists the 1,048 original-checkpoint evaluations, and
  `comparisons/20261031_adult_tabddpm_fix/valbest/scores_valbest.csv` the latest
  602 validation-best evaluations. Each dataset folder (`adult/`, `census_kdd/`, ...)
  holds per-run training histories (`*.epochs.csv`), reports, split manifests
  (`seed42_split.json`, `seed43_split.json`), validation-best results
  (`*.valbest.result.json`) and, where size permits, the full run records.
  Older namespaces' records are under `output/<namespace>/` and `data/<namespace>/`.
- Provenance: `source/<namespace>/` is a frozen copy of the `src/` that produced
  each result namespace. `scripts/reruns/` holds the launchers used for the
  targeted reruns, and `audit/` the dated diagnosis and verification notes.

Not included because of size (about 36 GB): fitted generators (`*.pkl`), labelers
(`*.pt`), downstream weights (`*.pth`), the 100,000-row synthetic tables and
per-row test predictions. These are regenerated by the steps below.

## Environment

The production runs used Linux with an NVIDIA GeForce GTX 1080 Ti (11 GB), driver
575.57, Python 3.10.21 and PyTorch 2.5.1 built for CUDA 12.4 (`environment/server-hardware.txt`).
Create a matching environment with either file:

```bash
conda env create -n tabularda -f environment/server-conda-env.yml
# or, in a Python 3.10 virtual environment:
pip install -r environment/server-pip-freeze.txt
```

`requirements.txt` lists the direct dependencies only. The runners require CUDA.
The validation-best replay also uses Linux-only facilities (`/proc/meminfo`, `resource`).
All commands below run from the repository root.

## Data

Raw data is downloaded on first use by `src/datasets.py`:

| Task | Source |
| --- | --- |
| Adult | UCI Machine Learning Repository id 2 |
| Census KDD | UCI id 117 |
| Covertype | UCI id 31 |
| News (regression) | UCI id 332 |
| Credit | OpenML id 1597 |
| MNIST12, MNIST28 | OpenML `mnist_784` version 1 (MNIST12 is a 12x12 binarized resize) |
| California Housing (regression) | scikit-learn `fetch_california_housing` |

Rows are partitioned before any preprocessing or fitting. The splitter groups
identical feature rows, uses split random state 42 for both experiment seeds, and
keeps a development partition separate from the test partition. Each preparation
writes `data/<namespace>/<dataset>/seed_<seed>/split_manifest.json`. To confirm
your inputs match the published ones, compare its `files.*.sha256` values with the
committed `<dataset>/seed42_split.json` and `seed43_split.json`. A mismatch means
the upstream source changed; it should be resolved before results are compared.

## 1. Real-data matrix

`scripts/run_corrected_matrix.py` prepares splits, fits generators, fits labelers,
generates 100,000 synthetic rows per table and trains the downstream networks.
Passing `--datasets` selects the corrected protocol: weighted loss with macro-F1
development selection for Census KDD, and a log target for News. Always choose a
new namespace; `corrected_v2` and the other committed namespaces hold the
original records.

```bash
NS=replication_v1
for SEED in 42 43; do
  python scripts/run_corrected_matrix.py --namespace $NS --seed $SEED \
    --datasets adult census_kdd credit covertype mnist12 mnist28 news california_housing \
    --generators ctgan tvae
  python scripts/run_corrected_matrix.py --namespace $NS --seed $SEED \
    --datasets adult census_kdd covertype mnist12 mnist28 news california_housing \
    --generators tabddpm --tabddpm-epochs 500
done
```

Settings are fixed in the code:

- CTGAN, TVAE and TabDDPM: 500 epochs, batch size 500.
- Downstream networks: dataset-specific (`src/modeling/models_folder/`); batch size 128,
  learning rate 0.001, at most 100 epochs, patience 30, development-loss checkpoint
  selection (macro F1 for Census KDD).
- Training arms: synthetic-only, and mix (all real training rows plus all 100,000
  synthetic rows).
- Labelers: Gaussian NB, Categorical NB, PCA/GMM, RF, XGB and DNN. News and Housing
  use PCA/GMM, RF, XGB and DNN.

TabDDPM was not run for Credit. Each run writes
`output/$NS/<dataset>/acc/<run>.run.json` with test scores, hashes and provenance.
`--stage classifiers --resume` continues an interrupted downstream stage without
repeating completed runs.

**Code versions behind the reported numbers.** Current `src/` includes every fix
applied during the study: removal of the SDV Faker transformer for Housing, the
corrected MNIST output head, the TabDDPM categorical-posterior normalization
(`audit/TAB_DDPM_PATCHES.md`) and the News log target. Most reported cells were
produced with these fixes. The exception is TabDDPM for MNIST12, MNIST28, News and
California Housing: those results (namespace `tabddpm_500ep_20261010_v1`) ran before
the posterior fix. Its pre-fix module is preserved at
`source/tabddpm_original_module/gaussian_multinomial_diffsuion.py`. Every run record
stores the `source_sha256` and Git `code_version` of the code that produced it,
and `source/<namespace>/` holds the matching `src/`.

## 2. Validation-best checkpoint selection

The headline tables report the checkpoint with the earliest maximum development
metric, chosen within each run's completed history. The metric is binary F1 for
Adult, macro F1 for Census KDD, Covertype and both MNIST tasks, and R² for News and
California Housing. The scope is the real-only baseline plus generated targets and
full/X-only RF, XGB and DNN relabeling: 14 evaluations per dataset, seed and generator.

Training saves only the development-loss checkpoint, so the selected epoch is
recovered by deterministically replaying training. The replay checks every epoch's
metrics against the saved history (to 1e-8) and requires that the original checkpoint
reproduce exactly, then evaluates the selected epoch on the test partition.

```bash
python scripts/checkpoint_recovery/build_valbest_inventory.py --namespace $NS --out output/valbest_$NS
cd output/valbest_$NS
N=$(python -c "import json; print(len(json.load(open('inventory.json'))))")
for i in $(seq 0 $((N - 1))); do python -u recover_one_fresh.py $i; done
```

Each job writes `jobs/<record>/result.json` containing `test_scores` and the
verification evidence. Run the replay in the same clone, on the same machine and
environment that produced the records, and with the same `src/`. Records store
absolute paths, and the replay refuses to run if `src/` hashes differently.

The original selections were made with `inventory.py`, `recover_one.py` and its
queues in `scripts/checkpoint_recovery/` (October 15–18) and with
`adult/tabddpm_fix_20261030/valbest/` (Adult TabDDPM, October 30). Those copies keep
their historical paths as provenance. `build_valbest_inventory.py` reproduces both
historical inventories' selected epochs exactly.

## 3. Statistical analysis and reports

- Repeated-measures ANOVA with Holm adjustment:
  `output/statistical_anova_gdrive_20261019/analyze.py`. Its frozen inputs and
  results are committed alongside it.
- Comparison tables and figures: `scripts/plot_recent_comparison.py`, the builders in
  `scripts/checkpoint_recovery/` and `scripts/build_corrected_results.py`, which
  aggregates `*.run.json` records.
- Manuscript exhibits: `papers/aaai27_relabeling/build_valbest_exhibits.py`,
  `build_simulated_exhibits.py` and `build_exhibits.py`. They read only the
  committed scores; compile instructions are in `papers/aaai27_relabeling/README.md`.

## 4. Simulated benchmark

`simulated_eval/` is a separate study with known data-generating distributions:
Gaussian, Grid, Ring and four Bayesian networks. Its design and metrics are
documented in `simulated_eval/README.md`.

```bash
python -m simulated_eval --output output/simulated_replication --device cuda
python -m pytest simulated_eval/test_benchmark.py -q
```

The reported run's per-run scores are in `output/simulated_all_20260930/per_run.csv`.

## Expected agreement

Generator fitting and GPU training are not bit-for-bit deterministic across
different hardware, drivers or library builds. Reruns on other machines should
therefore match the reported results at the level of effects and rankings across
the two seeds, not every digit. Within one machine and environment, the
validation-best replay is exact by construction.
